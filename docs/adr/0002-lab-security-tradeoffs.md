# ADR 0002: Осознанные компромиссы безопасности лабораторного стенда

## Контекст

Стенд пересоздаётся много раз, живёт в изолированной host-only сети и не содержит реальных данных.

## Решения

1. **`host_key_checking = False`.** После каждого `destroy/up` у ВМ меняются host keys, и Ansible иначе блокируется. В продакшене нужно проверять ключи или использовать SSH-сертификаты.
2. **Общий SSH-ключ для Ansible.** Ключ создаётся локально в `keys/`, исключён из git и копируется на bastion. В продакшене: отдельные ключи по ролям, ротация, секрет-хранилище.
3. **SSH hardening включён.** Вход по паролю и под root запрещён, конфиг лежит в `sshd_config.d/10-hardening.conf` и проверяется `sshd -t` до применения.
4. **Токен k3s** передаётся в `no_log` задачах, права на конфиг агента `0600`.
5. **Фаервол отключён на этом этапе** и будет включён вместе с политиками безопасности (этап 5).

## Последствия

Эти упрощения нельзя переносить на реальные окружения.
